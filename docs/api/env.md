# env

> Generated by `operon doc std/env.op`, parse-only API surface (signatures, marks, `##` docs). Behavioral docs live in SPEC.md; network/regulation graphs: `operon graph`.

## `gene env_get(name)`

The value of an environment variable, or null when it is unset OR the
read is denied. Never stresses. When the two cases must be told apart,
call the raw env(name) under stress/rescue yourself.

## `gene env_get_or(name, fallback)`

The value of an environment variable, or `fallback` when it is unset OR
the read is denied. Never stresses, "safe" means "never crashes the
program", not "silently grants access": denial still denies.

## `gene env_has(name)`

True when a granted read finds the variable SET; false when it is unset
OR the read is denied (one answer for two causes, documented). Tell the
causes apart with the raw builtin under stress/rescue.

## `gene env_granted(name)`

Grant probe, value-free: true when reading `name` would be permitted
(whether or not the variable is set), false when the capability gate
would refuse. The variable's value never crosses this call, use it to
shape error messages and feature flags without leaking secrets.

## `gene env_fetch(name)`

Option-shaped read: `some(value)` when set, `none()` when unset. A grant
refusal is NOT a value here: the interference stress propagates untouched
(no containment inside this gene). Pair with `?!` at the call site when
the caller treats a missing variable as its own early exit.

## `gene env_require(name)`

Loud read for variables a program cannot proceed without: the value when
set, a catchable `missing` stress when unset (message says so), and a
grant refusal propagates as `interference` untouched. The refusal kind is
preserved so a host can tell "forgot the grant" from "forgot to set it".
