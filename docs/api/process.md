# process

> Generated by `operon doc std/process.op`, parse-only API surface (signatures, marks, `##` docs). Behavioral docs live in SPEC.md; network/regulation graphs: `operon graph`.

## `gene process_run(prog, args)`

The full run() result map, or null on refusal / unspawnable program.
Never stresses. The map shape is {code, stdout, stderr, ok}; a timed-out
child still answers the map (code -1, ok false).

## `gene process_run_or(prog, args, fallback)`

The full run() result map, or `fallback` on refusal / unspawnable
program. Never stresses.

## `gene process_output(prog, args)`

The child's stdout as one string, or null on refusal / unspawnable.

## `gene process_output_or(prog, args, fallback)`

The child's stdout, or `fallback` on refusal / unspawnable.

## `gene process_lines_or(prog, args, fallback)`

The child's stdout split into lines (trailing empty piece dropped), or
`fallback` on refusal / unspawnable.

## `gene process_ok(prog, args)`

True only when the child runs and exits 0; false on refusal, unspawnable
program, timeout, or a non-zero exit (one answer, documented). Inspect
process_run yourself when the causes must be told apart.

## `gene process_succeeded(result)`

Shape-checked accessor: true/false from a run() result map's ok field,
null on anything that is not a result map (wrong type or missing field).

## `gene process_code(result)`

Shape-checked accessor: the exit code from a run() result map, null on
anything that is not a result map.
