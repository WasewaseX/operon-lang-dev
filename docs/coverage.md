### Methodology (call-site coverage, static analysis of the corpus)

- Static set: top-level `gene name(...)` definitions in std/*.op,
  found with the same regex strategy as the std module inventory in
  `scripts/gen_doc_stats.py` (pattern copied, not imported). The two
  inventories are expected to agree; docs/stats.json is the cross-check.
- Dynamic set: per corpus file, the `use std/<module> [as <alias>]`
  lines are read to learn which std modules that file pulls and under
  which namespace (`alias` if present, else the module name). A module's
  gene name is referenced when it appears in a call position in that
  file's body, as `ns.name(` or as a bare `name(`.
- Matching rules: comments and string-literal contents are stripped
  first; qualified calls count for the module bound to that namespace;
  bare calls count for an imported module defining the name, unless
  the file itself defines a gene of the same name; method-style
  `.name(` never matches the bare rule.
- Limits, stated so nobody over-reads the number: a call inside an
  untaken branch still counts (mentioned-not-called); a dynamically
  dispatched call (call(), gene values, maps of genes) may not count;
  a bare call can credit a same-named builtin to an imported std
  module; std/seq exports `sequence` definitions, not genes, and the
  pinned gene-def regex reports 0 functions for it, matching the
  generated inventory in docs/stats.json.
- Determinism: sorted inputs and outputs, no timestamps, no
  environment reads beyond the repo tree; two runs over the same
  tree produce byte-identical output.
- Reading the number: the qualified-namespace total is the hard floor,
  the combined total is the ceiling; the truth sits between them and
  this tool cannot narrow it further without executing the corpus.
